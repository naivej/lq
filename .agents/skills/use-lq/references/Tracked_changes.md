# Tracked changes

See `lq help tracked-changes` for the marker model, regions, and the per-position overwrite model. Operational rules that prevent mistakes:

- **Inspect the regions before editing a reviewed document.** `text:change(current)`, `text:change(inserted)`, and `text:change(deleted)` name the three regions; scope the next operation instead of treating visually similar text as one region. Diff view: `lq read file.lyx "text:change(current), text:change(deleted)" --text-only`; add `text:change(inserted)` for pending insertions. `read`/`dump` annotate tracked text by default.
- **Editing rejected text does not accept it.** The deleted text is preserved and the replacement becomes an adjacent new tracked change; the rejected region keeps its original author, so another author's replay-undo cannot resurrect it.
- **Replaying an edit that consumed another author's insert restores the consumed text as plain current text.** The consuming deletion replays the way LyX's reject restores a deletion — as unchanged text, not as the original insert (`Paragraph::eraseChar` overwrote the insert attribution at edit time). The original author's later replay in the same span can therefore re-add text; inspect the span with `--text-only` before a multi-author rollback.
- **Tracked markers live only inside a layout's text.** With tracking on, edits to preamble lines, `#` comments, header text, or inset metadata are rejected with `TRACKING_ERROR`; disable tracking for those surfaces or target layout text instead.
- **Tracking off vs on for a plain `set`.** Off: the inline properties around the replaced text are dropped (no dead markup). On: they are kept inside `\change_deleted`, so rejecting the change restores the original formatting.
- **Do not assume `--replace-all` always wipes.** A node with review history follows the per-position preservation path and keeps insets outside the new change pair.
- **Undo has two modes by syntax.** `lq undo file.lyx` is snapshot restore (one level); `lq undo file.lyx "<block selector>" ["substring"]` is author-scoped replay over a block's direct children, including Tabular `change=` when the match is the table. Use replay for per-task rollback, snapshot for the whole last mutation. See `lq help undo`.
- **Table row/column `change=` and cell `\change_*` are two replay targets.** `add-row` / `add-column` / `delete-row` / `delete-column` mark the row or column on the Tabular XML (`change="inserted"` / `change="deleted"`). Replay `undo` of the table (catalog `at`, or `inset[Tabular]`) reverts that author's row or column: an inserted row or column is dropped (cells included); a deleted row or column is unmarked (cell `\change_*` stay). Replay of a cell layout peels `--data` / cell `set` and leaves the row/column mark. Snapshot restore reverts both. A substring on a table must sit on only one axis (row or column) or nothing is reverted. The last remaining row or column is skipped.
- **Authors are matched by name, and existing `\author` lines are reused.** An `\author <id> "<name>"` line with an optional trailing email, or a negative LyX hash ID (LyX hashes name+email; the cast to int is often negative), is recognized and reused — no duplicate `\author` entry and no mis-attributed markers. A new name gets the next sequential ID above the largest positive ID already present.
- **Whole-layout tracked `delete` is per-position, not a blind wrap.** Adjacent same-author deletions merge into one region; already-deleted content keeps its original author (never re-attributed to the deleter); inline properties fold inside the deleted region so rejection restores formatting. A paragraph deleted through its last position ends inside the region with no trailing `\change_unchanged` — the byte-exact form LyX writes.
- **A content-less layout cannot be track-deleted.** A layout holding only font properties or an empty change region has nothing a marker can wrap (LyX discards a change region without text on read), so a whole-layout `delete` under tracking refuses with `TRACKING_ERROR` instead of reporting success while changing nothing. Disable tracking to physically remove the layout.
- **Do not `delete` a property node with tracking on.** LyX tracks changes on text, not on inline properties or header values (a change region with no text is discarded on read), so the command refuses with `TRACKING_ERROR`. Target the text the property formats instead — `lq delete file.lyx "layout[Standard] text:property(emph)"` — or disable tracking. `set` on a property value stays a plain untracked edit.
